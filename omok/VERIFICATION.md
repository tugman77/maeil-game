# 오목 승부 이유 표시 검수

대표님 피드백(2026-11-25)을 반영했다. 작업 가지는 `omok-result-explain`이며 공개 배포는 대표님 미리보기 승인 뒤 진행한다.

## 화면 동작

- 실제 다섯 연결은 굵은 노란 선·테두리, 마지막 수는 흰 테두리를 두른 빨간 네모로 표시한다. 가로·세로·대각선과 승패를 판 위에 적는다. 여섯 돌 이상도 기존 승리 규칙대로 전체 줄을 표시한다.
- 결과 화면으로 자동 전환하지 않는다. 판 아래 큰 **결과 보기**, 결과의 **판 다시 보기**로 오간다. 승패·최고 기록·오늘의 도전은 종료 순간 한 번만 기록한다.
- 기존 AI가 증명한 수순에 설명용 좌표만 덧붙였다. 열린 4·4-4는 서로 다른 지금 막을 빈칸을 파란 ×로, 4-3과 연속 4의 다음 공격 자리는 파란 ◇로 구분한다. 아직 동시에 두 곳을 막는 단계가 아닌 연속 4를 거짓 쌍사로 표시하지 않는다.
- 컴퓨터 기권도 표시한 판을 먼저 본다. 내 패배 확정 선택은 판 아래에 있으며 판을 덮지 않는다. **수순 보기**는 실제 증명에서 얻은 공격·응수를 번호로 한 수씩 보여 준다. 양쪽이 열린 곳에서는 한쪽을 막는 대표 예시이며 다른 끝이 남는다.
- 결과의 **수순 다시 보기**는 실제 대국을 처음부터 돌려 본다. 오늘의 도전에서 미리 놓인 첫 모양은 유지한다. 증명 수순과 실제 대국 수순은 실제 게임 상태를 수정하지 않고 별도 판으로 그린다.
- 밝음·다크 모드에서 같은 노랑/파랑 표식과 모양을 쓴다. 큰 글씨에서 한국어 단어 단위로 줄바꿈한다. OS의 `prefers-reduced-motion: reduce`에서는 애니메이션을 적용하지 않아 정적 선과 테두리만 남는다.
- 규칙, 탐색 후보·예산, 저장 버전과 키, 이어하기, 계속 두기 결정, 기록·출석·공유는 기존 흐름을 유지한다. `gostop/`, 장기, 스도쿠 생성기는 수정하지 않았다. 도움말 원본과 생성 결과를 함께 갱신했고 서비스 워커는 v33이다.

## 실제 Chrome 확인 및 범위

네이티브 Chrome에서 360px 프레임·큰 글씨로 대각선 승리 줄, 마지막 수, 결과 열기, 실제 수순 복기 첫 수를 확인했다. 다크 모드의 열린 4 돌·양끝 빈칸, 판을 덮지 않는 패배 확정 선택과 연속 4의 다음 공격 자리·수순 조작부도 확인했다. 이후 다른 맞고 작업과 Chrome 조작이 겹쳐 추가 브라우저 조작은 중단했다. 연속 4 전체 이전/다음 조작은 자동 DOM 검사로 검증했다. 실제 휴대폰, Safari/Edge, OS 동작 줄이기 설정의 실기기 렌더링은 미검수다.

로컬 검수 파일은 `/tmp/omok-result-review/diagonal-0-preview.html`이다. 메뉴에서 승리/컴퓨터 기권/패배 확정/연속 4와 밝음/다크를 고른다. 검수 파일은 메모리 저장소를 사용해 실제 브라우저 게임 저장을 덮어쓰지 않는다. 로컬 서버 열기는 실행 환경의 소켓 권한으로 차단돼 파일 방식으로 확인했다.

## 커밋 환경

현재 클론의 `.git/index.lock` 쓰기가 실행 환경에서 `Operation not permitted`로 거부됐다. 변경 파일은 현재 클론에 그대로 있으며, 같은 이름의 가지를 가진 `/tmp/omok-result-review/repo` 독립 복사본에 커밋하고 `/tmp/omok-result-review/omok-result-explain.bundle` 및 `.patch`를 만든다. main을 포함한 원격 push는 하지 않는다.
