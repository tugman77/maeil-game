제목: 매일게임 하루 한 게임 만들기
실행 방식: 자동 예약 없이 사용자가 직접 제작 지시를 할 때만 실행한다. 날짜 기준은 Asia/Seoul.
상태: 사용자 요청에 따라 수동 지시 방식으로 운영한다. 자동 예약은 사용하지 않는다.

사용자의 제작 지시를 받았을 때 따를 실행 지침:

사용자가 제작을 지시하면 https://tugman77.github.io/maeil-game/ 에 새 게임을 하루 한 개를 목표로 추가한다. 날짜가 바뀌었다는 이유만으로 작업을 자동 시작하지 않는다.
저장소는 tugman77/maeil-game, 로컬 프로젝트는 /Users/kimjunsik/My World/Media/Game/매일게임 이다.
먼저 저장소의 최신 CLAUDE.md, 적용되는 AGENTS.md, DAILY_GAME_PLAN.json, games.json을 읽고 원격 변경 사항과 작업 중인 변경을 확인한다.
이용자는 40대 이상이 두루 즐길 수 있어야 하며, 큰 글씨·선명한 대비·적은 조작 단계·명확한 선택 표시와 되돌리기·이어하기를 중시한다. 복잡한 메뉴·정밀 드래그·불필요한 반복 입력을 줄인다. 깊이 있는 전략 보드게임도 허용한다. 60대 이상 전용이나 유아적인 규칙으로 축소하지 않는다.
한국 40~60대에게 익숙한 게임 스타일과 오늘의 도전에 맞는 게임을 앞세운다. 현재 다음 순서는 장기 → 바둑(9줄부터) → 맞고 → 속담 완성 → 한글 단어 찾기 → 노노그램이며 전체 순서는 DAILY_GAME_PLAN.json을 따른다.
제작 목록에는 팩맨 스타일 미로 게임·틀린 그림 찾기와 추가 승인한 10종(같은 색 블록 지우기·버블 슈터·주차장 탈출·칠교놀이·물색 분류·윷놀이·보석 3개 맞추기·파이프 연결·직소퍼즐·땅따먹기)도 포함한다. 추천 목록을 다시 생성하지 말고 저장된 대기열 순서를 따른다.
한 번에 새 게임은 하나만 진행한다. 사용자가 주는 피드백을 매 작업 시작 시 확인하고 기존 게임의 수정 및 다음 제작에 반영한다. 별도로 보류하라는 요청이 없다면 게임마다 승인을 반복 요청하지 않는다.

1. 한국 날짜를 기준으로 DAILY_GAME_PLAN.json의 실행·완료 기록과 games.json의 실제 공개 목록을 확인한다. 이미 오늘 새 게임이 공개됐으면 중복 실행을 피한다. 사용자가 이후 명시적으로 다음 게임을 추가 요청하면 그 요청에 따라 한 게임을 진행할 수 있다. 과거 미실행분을 한꺼번에 여러 게임으로 보충하지 않는다.
2. backlog에서 첫 미완성 항목 하나를 고른다. 이미 같은 게임이 추가돼 있으면 중복 개발하지 않고 기록을 조정한다. 미완성 항목이 있으면 새 항목보다 이어서 완성하는 것을 우선한다.
3. 작업 시작 시 실행 날짜·게임 ID·기준 커밋·진행 상태를 계획의 runs에 남긴다. 다른 작업자가 같은 항목을 진행 중이면 동시에 실행하지 않는다. 이 JSON은 잠금 장치가 아니므로 다른 작업자가 같은 게임을 진행하고 있는지 확인한다.
4. 규칙과 필요한 컴퓨터 상대 수준을 먼저 확인하고, 기존 순수 HTML/CSS/JavaScript 구조와 공통 시작 화면·설정·기록·오늘의 도전·썸네일을 활용해 완성한다. 일일 목표를 위해 단순한 색상·이름 변경을 새 게임으로 세지 않는다.
5. games.json, 썸네일, 도움말 생성기와 설명 페이지, 소개, sw.js 파일 목록을 연결한다. 공통 난수와 스도쿠 생성기·기존 기록은 보존한다.
6. 새 규칙과 저장·이어하기·컴퓨터 차례·되돌리기·결과 기록을 검사하고 기존 회귀 검사를 실행한다. 실제 브라우저를 사용할 수 있으면 모바일·PC·큰 글씨·다크 모드를 확인한다. 브라우저 검수가 불가능하면 그 제한을 명시한다.
7. 통과한 완성본만 GitHub에 반영하고 기존 GitHub Pages 배포 성공을 확인한다. 다른 작업의 수정 사항을 덮어쓰거나 강제로 push하지 않는다. 미완성·검사 실패·접근 오류이면 무리하게 공개하지 않고 해당 게임의 진행 상황과 재개 방법을 남긴다.
8. 공개 성공 시 completed에 게임·한국 날짜·커밋·주소를 기록하고 backlog와 runs를 갱신한다. 완료로 표시하기 전에 실제 배포 결과를 확인한다.
9. 게임 이름·플레이 주소·주요 기능·검사 결과·남은 제한을 보고한다. 대기열이 소진되면 기존 목록과 겹치지 않는 전략·카드·퍼즐 게임을 같은 기준으로 선정해 추가한다.
